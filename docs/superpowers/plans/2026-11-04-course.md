# Course Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Materi dipaketkan jadi **course** yang bisa didaftari karyawan. Tiap course punya unit, perjalanan, dan progresnya sendiri. Beranda jadi kartu yang digeser antar course; level berhenti menyaring apa pun.

**Architecture:**
- `Course → CourseUnit → Lesson → Item`. Unit punya dua rasa: unit lesson (daftar `Lesson`) dan unit modul (`CourseUnit.moduleId` → bab-bab sebuah `Module`).
- `Lesson.unitId` adalah satu-satunya penanda "lesson ini punya rumah". Lesson tanpa `unitId` tidak muncul di jalur mana pun.
- `PATH_LESSON` berubah dari konstanta jadi fungsi `pathLesson(courseId)`. `groupPath` berhenti mengelompokkan per `topic`/modul dan mulai mengelompokkan per `CourseUnit`. Keduanya tetap satu-satunya sumber urutan — `/journey`, Beranda, sesi harian, sesi berbicara semua lewat `SessionService.path()`.
- Pendaftaran (`Enrollment`) menentukan course mana yang kelihatan; **bukan** menentukan kolam penguatan, yang tetap lintas course.
- Web murni tampilan.

**Tech Stack:** NestJS + Prisma + Postgres (`apps/api`), Next.js App Router (`apps/web`), Jest (unit `*.spec.ts`, e2e `test/*.e2e-spec.ts --runInBand`).

**Spec:** `docs/superpowers/specs/2026-11-04-course-design.md`. Baca dulu. Rujukan §-nomor di plan ini menunjuk ke spec itu.

5. **Impor ulang.** `lesson_code` yang sudah dimiliki course lain ditolak dengan nama course pemiliknya; `unit_order` yang sudah ada menimpa `unit_title`, tidak membuat unit kembar. Test di Task 10.

model Course {

  code      String @unique
  slug      String @unique

  order     Int
  status    ContentStatus @default(DRAFT)

}

model CourseUnit {
  id       String @id @default(cuid())

  course   Course @relation(fields: [courseId], references: [id])

  title    String

model Enrollment {
  userId       String

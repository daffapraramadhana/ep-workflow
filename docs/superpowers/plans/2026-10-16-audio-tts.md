# Audio TTS Natural Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Semua audio bahasa Inggris (listening, "Dengarkan contoh" UCAPAN, 🔊 frasa/dialog bab) menjadi file MP3 neural Kokoro yang dibuat sekali di server dan diputar sama di semua perangkat, otomatis untuk konten dari seeder, importer, dan admin.

**Architecture:** Modul Nest baru `src/tts/`: fungsi murni (normalisasi teks, parse skrip dialog, id klip sha256, encode MP3) + engine Kokoro di balik token `TTS_ENGINE` + `TtsService` (daftar klip saat membangun tampilan, sintesis lazy dengan dedupe/semaphore/timeout, pelepasan model saat idle) + `GET /tts/:id.mp3` publik. Tampilan sesi/bab hanya *mendaftarkan* klip (`TtsClip`) dan mengirim URL; sintesis terjadi saat audio diminta atau lewat CLI `tts:backfill`. Web memutar URL itu, jatuh ke suara browser bila gagal.

**Tech Stack:** NestJS 11 + Prisma 6 + Postgres (apps/api, jest unit + e2e supertest) · Next.js 15 + React 19 (apps/web, tanpa test runner — verifikasi `tsc`, lint, preview browser) · lib baru api: `kokoro-js@1.2.1`, `@breezystack/lamejs@1.2.7` (encoder MP3 pure-JS, LGPL-3.0, dipakai tanpa modifikasi).

**Spec:** `docs/superpowers/specs/2026-10-16-audio-tts-design.md` (disetujui 16 Okt — baca dulu; plan ini berargumen dari sana).

## Global Constraints

- Tiga repo terpisah: kode api di-commit di `apps/api`, kode web di `apps/web`, docs/deliverables/infra di root workspace. Jangan `git add apps/...` dari root.
- Fondasi: semua logika di BE; angka di tabel `config`; tanpa cron/background job/queue.
- `ENGINE_ID = 'kokoro-82m-v1.0-q8'`; model `onnx-community/Kokoro-82M-v1.0-ONNX`, `dtype: 'q8'`, `device: 'cpu'`.
- Suara: narator `af_heart`; dialog sisi kiri `af_heart`, sisi kanan `am_michael`. Jeda antar-segmen dialog 350 ms.
- id klip = 32 hex pertama `sha256(ENGINE_ID + JSON.stringify(segments))`; nama file `tts-{id}.mp3`; URL `/tts/{id}.mp3`.
- Config int (seed upsert `update:{}`): `TTS_ENABLED=1`, `TTS_MAX_PARALLEL=1`, `TTS_IDLE_UNLOAD_MINUTES=10`.
- `GET /tts/:id.mp3` publik; batas tunggu sintesis 30 000 ms → 503; header `Cache-Control: public, max-age=31536000, immutable`.
- `ttsText` maks 600 karakter; dialog maks 2 pembicara.
- MP3 mono, sample rate dari engine (Kokoro 24 000 Hz), 64 kbps.
- Test (unit & e2e) TIDAK PERNAH memuat model Kokoro — selalu engine palsu.
- `mediaFile` unggahan admin tidak pernah ditimpa/dikosongkan oleh TTS.
- Teks UI berbahasa Indonesia.
- `prisma` tetap di `dependencies` api (jangan "dirapikan").

## Review Focus

1. **Teks yang kosong setelah normalisasi** (mis. hanya emoji "🔊", atau hanya tanda baca) → tidak ada URL audio untuk item itu (tombol jatuh ke suara browser / tidak tampil), bukan klip yang 503 berulang. Ditest di Task 2 (`speakableText`) dan Task 5 (`content-specs`).
2. **Sintesis gagal sekali lalu berhasil** (engine melempar, atau `storage.put` gagal) → request pertama 503, baris `TtsClip` tetap belum `fileName`, request berikutnya mencoba lagi dan 200. Ditest di Task 4.
3. **iOS Safari meminta `Range`** pada `<audio>` → `GET /tts` harus melayani file lewat jalur `sendFile`/redirect yang sama dengan `/media` (bukan `res.send(buffer)`), termasuk tepat setelah sintesis pertama. Ditest di Task 4 (`Range: bytes=0-99` → 206).
4. **Pelepasan model idle saat sintesis panjang sedang berjalan** → model tidak dilepas sampai sintesis selesai; timer dihitung dari selesainya sintesis terakhir. Ditest di Task 3 (`IdleUnloader`).
5. **Sintesis lewat 30 dtk** → klien dapat 503 cepat, tapi sintesis tetap selesai dan menyimpan file; request berikutnya 200 tanpa sintesis ulang. Ditest di Task 4.
